# 戰鬥演出全景化設計

## 目標

修正訓練家選角與戰鬥演出目前的三個視覺斷裂：選角的瀏覽器式滑桿、各關卡背景缺乏辨識度，以及全景開場與小型棋盤背景之間的不連續。所有改動維持純 UI／演出，不能改變任何數值、隊伍、羈絆、商店、難度或戰鬥結果。

## 1. 選角改為舞台式輪播

- 移除底部水平捲動條。
- 顯示中心選中卡與兩側鄰近卡；以左右箭頭切換為主要桌面操作。
- 保留滑鼠滾輪、觸控拖曳與鍵盤左右方向鍵作為輔助操作。
- 卡片點選仍可直接選定角色。
- 維持十名既有角色、簡化名稱與純視覺身分，不顯示世代、檔名尾碼或任何數值。

## 2. 關卡背景以空間地標區分

背景差異不能只依賴不同色相。每個 scene token 至少要有兩項不同的構圖元素：天際線／視線方向、建築或地形輪廓、地面材質、空氣效果。

- 一般：林間道路、溫室、港灣或小型競技場。
- 四天王：洞窟、圖書館、水瀑斷崖或火山地形。
- 冠軍：聯盟殿堂、拱頂、柱列與地面反光。
- 場景仍由對手 ID 與關卡級別穩定決定，不讀取玩家隊伍或羈絆。

## 3. 邊緣小型立繪與全景戰鬥舞台

### 開場

- 使用先前選定的邊緣小型立繪方案。
- 左右訓練家立繪高度降為畫面約 24–30%，貼齊底角；中央留給環境與 VS。
- 一般戰鬥 1400ms，四天王與冠軍 2000ms，快速模式 600ms；點擊一次立刻跳過。
- 開場結束時只移除訓練家立繪，場景本身不更換。

### 戰鬥

- 採用 A「全景舞台」：戰鬥 phase 的整個可視戰鬥區（HUD、羈絆、隊伍、控制列）共用一張完整環境場景。
- 場景包含天空、遠景／地標、地面、薄霧與邊緣暗角；背景從頂部 HUD 延伸到底部控制列。
- 隊伍、羈絆與文字以陰影、細描邊、局部暗角維持可讀性。禁止新增大面積、硬邊半透明面板。
- 準備商店與其他 phase 維持目前 UI，不使用全景戰鬥背景。
- 戰鬥中的隊伍卡保留既有尺寸、可點擊範圍與資訊；只替換其後方環境層。

## 架構與測試

- 將選角輪播抽為 `TrainerCarousel` 或調整既有 `TrainerSelector`，管理目前索引與鍵盤／箭頭輸入。
- `battlePresentation.ts` 擴充明確的 scene descriptor，包含場景類別與地標變體；`BattleIntro` 和 battle phase 的背景共用同一份 descriptor。
- 背景層以 CSS 元素／變數實作，不引入外部圖片。
- 擴充 `test:trainer-presentation`：檢查無水平 scrollbar 類別、存在箭頭與鍵盤操作、開場與戰鬥共用 scene class、battle scene 可覆蓋整個 battle view。
- 維持並重跑 `test:balance-values`、`test:smoke` 與 `build`，以證明沒有數值或模擬回歸。

## 非目標

- 不新增訓練家能力、初始單位、數值獎勵或背景效果。
- 不為準備商店、教學或結算頁全面重做主題。
- 不新增外部或未授權素材。
