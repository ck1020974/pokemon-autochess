# 明亮寶可夢冒險 UI 設計

## 目標

將主頁、版本選擇、難度選擇、教學起始視窗與角色選擇統一為明亮的「冒險道路」體驗。非戰鬥流程使用同一套天空、雲層、遠山、草地與道路景深；戰鬥流程維持依關卡變化的全景舞台。

此次變更涵蓋呈現、互動、驗證，以及既有 lint 錯誤的行為保留式修正。不得更改遊戲數值、角色數值、羈絆、敵人資料、遊戲流程規則或戰鬥規則。

## 視覺系統

- 建立共用的非戰鬥背景層：淺藍天空、暖白雲、低飽和遠山、草地與往遠方延伸的道路。
- 版本、難度與教學使用暖白、半透明資訊面板；主要文字為深青色；僅以金色標示確認、目前焦點與主要行動。
- 移除現有深色漸層、黑色玻璃卡、強烈陰影與發光邊框。保留按鈕的明確 focus 樣式與足夠對比。
- 戰鬥中的 `battle-stage-shell`、關卡場景映射與 Battle Intro 保持原有責任範圍；不將統一的道路背景套用到戰鬥中。

## 畫面與元件

### 主頁、版本與難度

- 將目前三個固定 `startup-overlay` 共用為同一個冒險場景外殼與一致的標題、面板、按鈕語意。
- 版本與難度的選項保留現有資料、雙擊確認行為與禁用狀態；視覺改成較輕量的白色半透明選擇面板。
- 載入進度採金色細線與深青文字，維持既有載入狀態與順序。

### 教學起始視窗

- 將 `TutorialModal` 由深色遮罩與深色面板改為冒險背景上的暖白半透明對話面板。
- 保留「開始教學」與略過／關閉的現有 callback 與教學步驟，不改變教學內容或觸發時機。

### 角色選擇

- 移除角色卡片的背景、邊框、卡片內名字、狀態文字、左右箭頭與所有卡片式 glint。
- 將十位角色維持為同一個循環輪播：中央角色最大且完整可見；前後相鄰角色只從左右邊緣露出部分立繪；更遠角色隱藏。
- 中央角色只使用柔和金色光暈、地面光圈與縮放作為選取焦點，不加入卡片外框。
- 畫面底部統一顯示「點擊角色開始旅途」。中央角色點擊呼叫既有 `onSelect`；點擊側邊露出的角色只切換焦點。
- 桌面版在畫面左右側設置無視覺按鈕的感應區。指標進入後等待約 180ms 切換一位；仍停留時每約 420ms 再切換；指標離開或回到中央時清除所有計時器並停止切換。
- 鍵盤左右鍵與 Enter／Space 維持可用。行動裝置不啟用 hover 自動切換，保留既有左右滑動；點擊左右側露出的角色可切換，點擊中央角色開始。
- 使用 `prefers-reduced-motion` 關閉非必要轉場；感應區不應阻擋中央角色的點擊與鍵盤焦點。

## 實作邊界

- 主要調整檔案：`src/App.tsx`、`src/index.css`、`src/components/TutorialModal.tsx`、`src/components/TutorialModal.css`、`src/components/TrainerSelector.tsx`、`src/components/TrainerSelector.css`。
- 如需共用非戰鬥背景，新增僅承載視覺的 UI 元件或 CSS 類別；不得耦合到 engine、models、data 或 presentation 的戰鬥判定。
- 更新 `scripts/verify-trainer-presentation.mjs`：驗證移除箭頭、存在側邊感應區與計時邏輯、中央選取仍呼叫 `onSelect`，以及 battle engine 仍不引用 `selectedTrainer`。
- 修正現有 ESLint 報告的 TypeScript 與程式風格問題（例如 `any`、未使用變數與區塊作用域），只做等價型別與語法整理；每一群修改後都以 smoke 與平衡驗證保護既有遊戲行為。

## 驗證

1. 執行 `npm run lint`，預期零錯誤。
2. 執行 `npm run test:smoke`、`npm run test:balance-values` 與更新後的 `npm run test:trainer-presentation`。
3. 執行 `npm run build`。
4. 本機瀏覽器流程檢查：載入、版本選擇、難度選擇、教學起始視窗、角色感應區的首次與連續切換、中央點擊開始、手機寬度下的滑動與側邊點擊，以及進入戰鬥後的關卡全景背景。
