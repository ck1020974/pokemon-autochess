# 場景微調與場地選擇發布計畫

**Goal:** 完成作者指定場景修改，將同一組 SVG 套用遊戲，發布 GitHub Pages。

**Architecture:** 場地在玩家選定對手時抽取並存入 React state，開戰演出與戰場共用該值。純函式依進度與敵方核心隊伍的羈絆選擇候選場景，使用可注入亂數與近期場景避重複；不更動戰鬥計算或隊伍生成。

**Tech Stack:** Python SVG、React、TypeScript、Vite、Node assert、Playwright、GitHub Pages。

## 作者要求與具體設計

- 02 減少樹木，移除兩側異色地面形狀，統一林地色調。
- 04 移除過大的雲；05 縮短窗戶並增加窗下實牆與窗台，使窗戶不直接接地；06 使用水平直岸；09 移除右側柵欄。
- 保留原 01～20 編號；21 為研究所，22、23 為薰衣草與白金殿堂。白金採白石柱、金飾和深色拱廊，原 01 青藍殿堂保持不變。
- 四天王進度（8～11 勝）一律在五色競技場隨機；冠軍進度（12 勝起）一律在三色殿堂隨機。
- 一般對手依核心隊伍實際羈絆 ID 配景：Fire→熔岩、Water→湖畔／海港／海灘／海洋、Grass／BugBite→森林／草原、Snow→冰川、Cave→沙漠／道路、Ghost／Psychic→圖書館、Charge／Hard→競技場。沒有明顯主題的混合隊伍從一般場景隨機；多候選時避開最近兩張，池耗盡時先排除上一張。
- 研究所用在無限版角色池選擇及無限版開局備戰；商店、休息中心與選敵營地保留既有用途。
- 後續作者修訂：研究所寶貝球上紅下白，取消中間螢幕與大桌抽屜，右上改黑板塗鴉；16 休息中心門上無醫療符號；其他四色競技場螢幕圖案加深加粗。
- 本輪包含先前尚未發布的全部已確認背景。保留純 SVG，禁止生成圖片。
- 作者已明確要求完成後上傳，驗證通過後推送 main，等待 Pages 成功並檢查線上版本；不再重複請求發布許可。
