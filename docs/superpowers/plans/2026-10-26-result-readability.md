# 勝敗與對戰訊息可讀性

**目標：**依使用者回饋恢復單場勝敗、平手、通關及冒險失敗底色，改善對戰訊息，說明實際場景規則並發布。

**設計：**沿用 React SPA 與既有 CSS，無 Tailwind 或元件庫。恢復上次修改前的結果配色；保留無滑桿紀錄、透明頂部資訊列及場景選擇時機。對戰訊息採既有深藍底與淺色文字，移除降低整行透明度，最新一則加粗，訊息多寡不影響最新一則判斷。

**檢視：**結果文字直接疊在複雜場景（§7.2），訊息灰字加 30% 透明度（§5.6）會失去可讀性。此次只修這兩處。

- [x] 恢復結果底色與相應文字色，對戰訊息樣式集中到 CSS。
- [x] 從實際版本核心隊伍與場景函式產生完整對應表。
- [x] 建置、呈現及場景檢查通過；唯讀審查無阻擋問題。
- [ ] 桌機及橫向手機驗證後發布，確認 Pages。

訊息的最壞情境以純白場景與 94% 深藍底合成計算：最新訊息 11.42:1、較早訊息 8.57:1。已檢視桌機與手機橫向實際畫面，手機訊息移除空的徽章區並縮小間距。

瀏覽器測試採臨時高／低數值單位驗證真實勝敗流程，不改遊戲規則。基本攻擊可能完全沒有文字紀錄，故不以「每次對戰一定有訊息」作假設；勝利測試改用保證發動開場招式的戴魯比，另覆蓋僅一筆訊息的最新一則判斷。視覺測試隔離既有音樂中斷競態。
