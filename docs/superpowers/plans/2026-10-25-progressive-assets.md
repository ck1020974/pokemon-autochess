# 圖片載入修正計畫

作者要求：修復角色、寶可夢、對手、獎勵與教學圖片漏載；進度接近實際比例；首頁即預載，入局後持續補載。沿用本次遊戲修正及上傳的授權，完成驗證後更新線上版本。

## 根因證據

- 532 個程式引用的 public 圖片路徑均存在。public 圖片約 9 MB，12 首音樂合計約 84 MB。
- 舊載入固定設為 20／60／100%，圖片 onerror 也算完成，沒有重試、併發限制或共用去重。
- 僅選版後開始大量載入，後期圖片再延後 2 秒；玩家角色、部分教學對手與進化鏈漏出預載集合。
- Service Worker 每次都先找網路，已快取圖片仍會等網路，容易重複下載。

## 實作

- [x] 先建立失敗測試，涵蓋下載去重、優先順序、併發限制、位元組進度、失敗不算完成、自動及手動重試。
- [x] 用 build/dev 前置腳本產生圖片／音訊大小清單與內容版本；驗證所有引用路徑與 Linux 大小寫。
- [x] 共用 AssetLoader 佇列：最多 4 個下載，背景最多 2 個，音樂最多 1 個且排在圖片之後；讀取完整回應、圖片解碼完成後才完成；有限時、重試、恢復連線補載。
- [x] main 進入即開始全部圖片背景下載。核心包含選角與獎勵；選版後優先準備所有寶可夢圖片、該版對手與完整教學素材；入局後繼續其餘圖片與音樂。畫面目前／即將用到的資源可提升優先序。
- [x] App 使用共用進度，按實際檔案大小及已收取位元組計算；載入失敗顯示可重試，不假裝 100%。移除舊大量 Image 及大音樂阻塞流程。
- [x] 圖片採有內容版本的快取優先，程式／HTML 維持網路優先；快取清理只處理本遊戲，不刪其他專案快取。
- [x] 驗證單元測試、真實瀏覽器首次／快取載入、失敗重試、教學、選角、選敵與獎勵圖片、build 與既有測試。已修正唯讀審查提出的 HTTP 舊快取問題，並補測 Range 隔離和當前版本快取隔離。
- 發布步驟：提交至 main 後等待 GitHub Pages 成功，核對正式站 SW 與新入口程式。

2026-10-26：594 個遊戲圖片網址無破圖；54 個不同進度值；暫時故障、自動重試、手動重試、入局後續載和正式建置離線圖片測試通過。708 個點陣圖檔案完整，素材佇列／快取／覆蓋、建置、trainer-presentation、battle-scenes 及 smoke 回歸通過。
