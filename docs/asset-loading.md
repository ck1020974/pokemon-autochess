# 圖片與音訊預載

首頁啟動即共用同一個載入佇列。先準備選角、教學和獎勵等核心圖片，同時偷跑其他圖片；選版本後提升寶可夢及該版本全部對手的優先序，完成圖片後才開放難度選擇。入局不會停止佇列，其餘圖片和音訊繼續載入。

- 圖片最多 4 個下載同時進行；低優先序工作最多 2 個，保留空間給目前需要的素材。
- 大音樂檔排在圖片後，最多同時 1 個；開場音樂等版本圖片就緒後才播放。
- 進度採實際檔案位元組大小加權，接收資料時持續更新。下載並解碼成功才算圖片完成。
- 每次請求有 20 秒逾時，失敗自動重試最多 3 次。最終失敗不會算 100%，載入畫面提供手動重試；恢復連線或回到分頁也會補試。
- SW 的媒體快取採內容版本命名。命中可立即使用，未命中會重新向網路取得，避免舊 HTTP 快取灌回新版本。HTML、CSS、JS 維持網路優先；只清理本遊戲的舊快取。
- 同 URL 的完整音訊與 Range 串流分開追蹤，避免將片段誤認為完整下載。

`npm run dev` 和 `npm run build` 會先執行 `scripts/generate-asset-manifest.mjs`，掃描媒體大小與內容指紋，更新 `src/loading/assetManifest.json` 和 SW 快取版本；內容相同不重寫檔案，避免開發中無謂重載。新增素材時執行這些命令即可，不需手填清單或檔案大小。

## 檢查

- `npm run test:assets`：佇列去重、優先序、限流、位元組進度、失敗重試、媒體快取版本、Range 隔離、全部版本的素材覆蓋和 Linux 檔名。
- 開啟 `npm run dev` 的 5173 後執行 `node scripts/check-asset-loading.mjs`：首頁預載、暫時失敗、進度變化、進場後繼續載入、選角／商店／選敵及所有圖片解碼。
- 另外開啟 `npm run preview -- --host 127.0.0.1 --port 5174`，執行 `node scripts/check-asset-recovery.mjs`：持續失敗與手動重試，以及正式建置的 Service Worker 離線快取。

2026-10-26 驗證：708 個 public 點陣圖原檔完整；瀏覽器測試 594 個遊戲圖片網址全部正常，進度出現 54 個不同值，暫時失敗與手動重試均成功。程式未改動戰鬥規則、平衡及影片主稿。
