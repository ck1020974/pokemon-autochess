# 手機角色與進化選項更新（2026-11-07）

## 行為

- 手機隊伍不再隨槽寬把圖片壓縮到約 50px；小型橫向手機至少 64px，844px 寬約 72px，932×430 保留 100px。保留每方五個固定邏輯槽，圖片可略微重疊，兩隊仍有間距。
- 手機商品固定 84px 寬、圖片 76px，七格放不下時只橫向捲動商品列；刷新鈕固定。整頁不產生水平捲軸。
- 伊布依其他隊友的實際羈絆計數抽選。排除本體、正在合成消耗的來源及共用接棒；最高羈絆對應型態的相對權重為 2，其他為 1，並列皆加權。最高羈絆沒有對應型態時仍均勻抽選。已進化型態升三星不重抽。
- 例：只有潮旋對應型態加權，水伊布機率為 2/9，其餘各 1/9。這是兩倍相對權重，會正規化總機率。
- 非無限模式冠軍戰，優先取三種不同難度並由低至高排列；所有選項只用未擊敗者。不夠三種時使用仍可挑選的人選，不補入已擊敗者。無限冠軍不強制分散難度。
- 對手標籤依版本、階段、遊戲總難度的正式引擎共同基準校準，保留原敵隊數值。詳見[校準方法](對手難度校準-20261107.md)。教學首戰固定三位小剛保留。

## 驗證與證據

`verify-eevee-evolution-weights.mjs` 包含抽樣權重、並列、家族去重、八種型態與拖曳／連鎖／指定購買／滿隊購買四種實際合成入口。

`verify-opponent-choice-diversity.mjs` 檢查未擊敗來源、種類不足、無限冠軍例外與階段門檻；`verify-opponent-choice-ui.mjs` 透過原生手機介面開啟選項，核對三種難度及僅剩一人的情況。

`verify-mobile-unit-sizes.mjs` 檢查 667×375、844×360、844×390、932×430、1280×720，包含安全區、七商品橫滑、刷新鈕位置、雙方五隻與空第5槽。羈絆逐側對照固定第5槽量測，不以圖片或最後占用角色定位。截圖與量測留於 `output/mobile-unit-sizes-20261107/`。

保留先前 iPhone 主畫面模式的安全區與直向捲動修正。未更動 v9 影片與錄影副本。
