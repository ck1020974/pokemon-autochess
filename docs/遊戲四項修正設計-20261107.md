# 遊戲四項修正設計（已核准並實作）

範圍：正式遊戲 `pokemon-autochess` 的原始碼與回歸驗證。影片 v10、錄影副本、採用旁白與字幕保留。本次不包含發布或重新出片。

## 1. 上方資訊列

準備、戰鬥及各種場景統一使用不透明的淺薄荷色底、深色文字，移除依場景切換的底色與文字陰影。桌面與手機皆適用；保留手機安全區與置頂行為。實際重現覆蓋情境，修正造成模糊或遮擋的層級／濾鏡來源，不單純提高 z-index。正式確認對話框仍維持原生遮罩行為。

目前證據：`src/index.css` 手機規則分別指定準備 rgba(225,244,233,.98)、戰鬥 rgba(16,29,45,.98)；`src/presentation/battleScenes.css` 桌面資訊列透明，文字依場景變色。模糊覆蓋原因尚待瀏覽器重現。

## 2. 夢幻分身

分身以戰鬥開始、敵方難度倍率完成後、開場招式與羈絆加成前的數值快照為基準，取該時點最大生命與攻擊並以滿血召喚。保留星級、動態羈絆、死亡槽位與沉默限制；分身不再召喚分身。動畫及無動畫引擎檢查一致性。

目前證據：動畫引擎死亡事件直接傳入 `unit.stats.maxHp` 與 `unit.stats.attack`，會讀到戰鬥中的變化。現有 `openingStats` 已提供上述時點快照，可沿用。無動畫引擎未找到夢幻死亡召喚註冊，須補齊並驗證。

## 3. 伊布進化排除三星型態

伊布隨機選進化型前，排除隊伍已有三星角色的相同進化型，以型態 ID 判斷。其餘候選保留原本羈絆權重並重新計算總權重，涵蓋一般升二星與直接升三星；排除正在被合成消耗的來源。既有二星型態升三星保持原型態，避免擅自改變已確定的進化路線。

目前證據：`GameLoop.performEeveeEvolution` 的八型態陣列沒有三星排除條件。正常隊伍最多五槽，不會出現八種型態全部被封鎖的情況；仍需避免異常資料造成未定義型態。

## 4. 無限模式選卡退場

推薦：未選卡片在約 400 毫秒內整張縮小至約 96%、下沉約 10px 並淡出，使用平滑緩出。移除鋸齒 clip-path、旋轉與灰階效果；選中卡片保持清楚，等待動畫後才套用選擇。減少動態效果偏好下使用短淡出。維持雙擊確認與處理期間禁止重複選擇。

替代方案：僅淡出最安靜；柔光溶解更有魔法感，但增加濾鏡與視覺干擾。推薦縮小淡出，辨識清楚且與既有介面相容。
